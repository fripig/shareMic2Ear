# shareMic2Ear

在瀏覽器裡把一支或多支麥克風混音後，即時導到指定的音訊輸出裝置。零依賴、零建置，可安裝成 App、離線可用，直接部署到 GitHub Pages。

**線上版本：** https://fripig.github.io/shareMic2Ear/

## 功能

- 列出系統所有音訊輸入／輸出裝置，並依名稱推測標示藍牙裝置
- **多支麥克風同時收音並混成一路輸出**，每支有獨立的音量、靜音與電平表
- 監聽進行中可隨時增減麥克風，不需停止重來
- 指定輸出到哪個耳機／喇叭，切換時即時生效
- 總音量與全部靜音（指數漸變，不會有喀噠聲），個別與總音量都可推到 400%
- **人聲增強**：可即時切換的動態壓縮器 + 8 dB makeup gain，用來補回關閉自動增益後偏低的音量
- **低電平自動偵測**：連續 8 秒的最大電平低於 -35 dB 時主動提示補救方式
- 混音輸出的音量表（RMS + peak hold）、麥克風數、取樣率、估計延遲
- 關閉 `echoCancellation` / `noiseSuppression` / `autoGainControl`（預設全關，可切換）
- 監聽裝置變化，藍牙連上或斷開時自動更新清單，運作中的裝置消失會自動移除
- **PWA**：可安裝到主畫面以獨立視窗開啟，離線也打得開；有新版本時提示而不強制重新載入
- **繁體中文／English 介面**：依瀏覽器語言自動選擇，右上角可手動切換並記住選擇，監聽中切換不會中斷音訊

## 音訊架構

```
麥克風 A ──┬─> AnalyserNode（旁路，個別電平表）
           └─> GainNode（個別音量／靜音）──┐
麥克風 B ──┬─> AnalyserNode                │
           └─> GainNode ───────────────────┤
                                           v
                              masterGain（總音量）
                                     │
                    ┌────────────────┴────────────────┐
                    │ 直通                  壓縮器 ──> +8 dB │   ← 「人聲增強」切換
                    └────────────────┬────────────────┘
                                     v
                                  outBus ──┬─> AnalyserNode（混音電平表）
                                           └─> 輸出裝置
```

AnalyserNode 一律掛成旁路，不在主訊號路徑上，因此不增加延遲。

## 安裝成 App（PWA）

| 平台 | 怎麼裝 |
|---|---|
| Chrome / Edge（桌面） | 頁面上方會出現「可以安裝成 App」提示，按「安裝」；或用網址列右側的安裝圖示 |
| Chrome（Android） | 同上，或從選單「加入主畫面」 |
| Safari（iOS） | 分享選單 → 加入主畫面（iOS 不提供安裝提示 API，所以頁面上不會有安裝按鈕） |

安裝後從主畫面開啟，沒有網址列，版面會自動避開瀏海與 home indicator。

**離線**：Service Worker 會預先快取頁面、manifest 與圖示，沒網路一樣打得開。
音訊處理本來就全在本機，離線不影響任何功能。

**更新**：採 stale-while-revalidate——先用快取讓頁面立刻開啟，同時在背景抓新版。
抓到新版時只會顯示「有新版本／重新載入」提示，**不會自動重新載入**，
因為重新載入必然切斷正在進行的監聽。監聽中收到提示時，文案會提醒你方便再按。
按下重新載入會先停止監聽釋放裝置，等新版 Service Worker 接手後才重新載入。

## 檔案結構

```
index.html               全部的 UI 與音訊邏輯，內嵌 CSS、JS 與中英文字典
sw.js                    Service Worker（離線快取與更新通知）
manifest.webmanifest     PWA manifest，路徑全用相對路徑
icons/                   192／512／maskable 512／apple-touch-icon
```

`sw.js` 必須是獨立檔案（Service Worker 無法內嵌），其餘一樣沒有建置流程。
manifest 與快取清單都用相對路徑，因此部署在 GitHub Pages 的子路徑下也正確。

## 部署到 GitHub Pages

```bash
git remote add origin git@github.com:<你的帳號>/shareMic2Ear.git
git push -u origin main
```

到 repo 的 **Settings → Pages**，Source 選 **Deploy from a branch**，branch 選 `main`、資料夾選 `/ (root)`，儲存後等一分鐘即可。

不需要 GitHub Actions，也不需要任何建置流程。

## 本機測試

`getUserMedia` 與 Service Worker 都需要安全內容。`localhost` 被視為安全，
直接開檔案（`file://`）則不行——PWA 的部分會安靜跳過，其餘功能仍可運作：

```bash
python3 -m http.server 8000
# 開啟 http://localhost:8000
```

## 瀏覽器支援

輸出裝置的選擇依賴 `setSinkId`，各家支援程度不同：

| 瀏覽器 | 選擇輸出裝置 | 走的路徑 |
|---|---|---|
| Chrome / Edge 110+（桌面） | ✅ | `AudioContext.setSinkId()`，延遲最低 |
| Firefox 116+（桌面） | ✅ | `<audio>` 元素轉送，多約 20–100 ms 延遲 |
| Safari（桌面） | ❌ | 只能輸出到系統預設裝置 |
| **Chrome / Firefox（Android）** | ❌ | `setSinkId` 只在桌面版提供，路由由系統掌管 |
| Safari（iOS） | ❌ | 同上，需從控制中心切換 |

程式會自動偵測並選擇可用的路徑。無法選擇時會依實際平台說明原因與該去哪裡切換，
並把輸出下拉整個收起來，而不是留一個點不動的選單。

### 行動裝置

網頁在 Android 與 iOS 上都**無法**指定音訊輸出，只能從系統層切換：

- **Android**：連上藍牙耳機後，從通知列下拉，點媒體通知右上角的輸出／投放圖示。
- **iOS**：從控制中心的音訊卡片切換。

Android 還有一點要注意：網頁使用麥克風時，系統會把音訊視為**通訊用途**，
藍牙耳機因此走 HFP 模式（音質降低），也可能被強制路由到聽筒或喇叭。
若聽到嘯叫就代表聲音走了喇叭。

### 診斷資訊

頁面底部有一個「診斷資訊」摺疊區，列出偵測到的輸出路徑、平台、裝置數與 UA。
回報問題時附上這段內容最省事。

## 已知限制

這些是瀏覽器與藍牙協定本身的限制，不是實作問題：

- **無法配對藍牙裝置。** Web Bluetooth 只能操作 BLE GATT，碰不到 A2DP／HFP 音訊裝置。配對必須在系統設定完成，本頁只能列出已連線的裝置。
- **藍牙裝置的標示是用名稱猜的。** Web API 不提供裝置的連線類型，只能靠字串比對，不保證準確。
- **藍牙耳機當麥克風用會降音質。** 一旦作為輸入裝置，會從 A2DP 切換到 HFP 模式，取樣率掉到 16 kHz 以下、立體聲變單聲道。想要好音質，輸入請用有線或內建麥克風，只讓輸出走藍牙。
- **藍牙有 100–300 ms 傳輸延遲。** 要真正低延遲的監聽請使用有線耳機。
- **多支麥克風會互相干擾。** 若它們在同一個空間，會收到彼此的聲音，混音後產生梳狀濾波（聲音變空洞、有金屬感）。這是物理現象，不是程式問題。
- **同時開多支藍牙麥克風容易失敗。** 會撞到藍牙頻寬與驅動限制，可能有裝置開不起來或聲音斷續。建議一次只用一支藍牙輸入。
- **關閉自動增益的代價是音量偏低。** 預設關掉 `autoGainControl` 是為了音質，但代價是你聽到麥克風的原始電平，多數麥克風都偏小聲。用「人聲增強」或把音量往上拉補回來，仍不夠就開啟自動增益。
- **回授風險。** 用喇叭而非耳機播放時，麥克風會收到自己的聲音形成嘯叫。程式啟動時會從靜音淡入以降低衝擊，但無法根治——請戴耳機。
